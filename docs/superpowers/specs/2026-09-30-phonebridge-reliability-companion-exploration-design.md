# PhoneBridge 可靠性、日常陪伴与探索日志设计

## 目标与现状

在现有单用户、单节点 PhoneBridge 上，先收紧隐私删除与离线同步，再补足日常陪伴和现实探索的可持续体验。Android 与 Web 都提供完整操作，仍以沉浸舞台为默认入口；不引入多人、必需的付费 AI、原图上传或精确位置轨迹。

当前实现已具备隐私中心、加密导出/备份、聊天与记忆控制、20 个 Mote、探索奖励收据、CameraX/ARCore 生命周期与降级路径。最新实现提交及交接 CI 已通过；剩余主要缺口是隐私删除历史只保留最近 100 条，以及 Xperia 上扫码、隐私界面、语音/探索/AR 和长时运行的本轮实机证据。

## 设计决策

### 1. 删除版本与旧版迁移

- 服务端 `privacy-audit` 状态升级为带 `categoryRevisions` 的持久版本；每个隐私类别的版本单调递增。最近 100 条删除回执可继续用于展示历史，但不再承担离线删除同步的正确性。
- `GET /api/privacy/overview` 返回各类别当前 revision 与迁移状态；删除回执和 `privacy.deleted` 事件返回本次涉及类别的新 revision。
- 新版 Android 在本地保存已应用的类别 revision；outbox 事件携带创建时看到的 revision。服务端拒绝低于当前 revision 的事件并返回明确业务拒绝，客户端清理相应旧缓存与队列后再恢复正常同步。未带 revision 的旧客户端只在该类别 revision 仍为 0 时按旧协议接收；类别发生过删除后，服务端拒绝无 revision 写入并要求升级，防止旧客户端重新写入已删除内容。只读接口与 ACK 的既有字段保持兼容。
- 若旧版存档无 revision 且保留的回执数恰好达到上限 100，首次升级标记所有旧类别的历史存在不确定性，并暂停相关 outbox。界面逐类展示本机缓存/待发数量，用户选择“清除本机缓存”或“保留”：清除会移除该类 Room/缓存/outbox；保留会保留本机内容，但将旧 outbox 隔离为只读且可导出，不自动重放。完成选择后才恢复同步；用户新建的数据使用当前 revision。
- 若旧回执少于上限且无未完成删除，按已有记录迁移，不弹不确定性确认。删除重试、进程重启和重复 eventId 均不得丢 revision 或重复清理。

### 2. 日常仪式与个人目标

- 新增可选的专注计时、散步观察、睡前回顾。活动可暂停、跳过或中断；不设连续签到、逾期惩罚、强制打卡或默认主动提醒。散步观察无需定位/相机权限；睡前回顾以文本为主。
- 新增“日常”隐私类别，导出和删除覆盖活动记录与用户输入；保持现有默认不自动写入长期记忆的规则。
- 个人目标支持用户创建目标、查看进度和里程碑。用户显式请求后，当前选定 provider 可生成可编辑的步骤草案；网络 provider 失败只回退本地规则，不切换备用联网 provider。草案未确认前不创建持久任务；确认后才创建带 `goalId` 的普通任务，不触发工具自治。
- 新增“目标”隐私类别。删除目标会级联清理其专属里程碑、关联任务、Attention 和审计；清理“任务”类别时保留目标定义并将受影响里程碑重置为未关联，避免悬空引用。每类新增数据均参与服务端加密导出、Android 本地清理和 outbox 过滤。
- Android 与 Web 使用相同的数据模型和服务端接口；Android 入口从沉浸舞台抽屉进入，Web 放入现有工作台，不新增启动设置页。

### 3. 探索日志

- 日志由已确认的 Reality 奖励收据生成，展示时间、粗区域、线索类别、当前 Mote 的观察提示和已结算奖励；未确认的离线事件只显示为待同步，不伪装成已获得奖励。
- 复用现有 `progress` 隐私类别；导出/删除与其余成长数据一致。日志不复制原图、不保存精确地址或连续轨迹，也不引入自由文本日记字段。
- Android 与 Web 均可按时间查看并回到相关遭遇；奖励仍只由现有幂等收据结算，日志本身不产生额外奖励。

## 接口与数据兼容

- 扩展现有隐私 overview/delete/receipt 与 `privacy.deleted` 协议，增加类别 revision 和旧档案迁移状态；保留现有字段、类别和旧客户端读取路径。
- 增加例程与目标的持久化读取/写入接口；所有写事件继续使用 `eventId` 幂等。目标步骤建议和确认分离，只有确认接口才创建关联任务。
- 探索日志优先作为 Reality 收据投影提供，不重复建立奖励账本。
- 新增隐私类别：`routines`、`goals`；探索日志归入 `progress`。旧状态读取时缺失字段取安全默认值，迁移失败时暂停对应 outbox，而不是静默清除或重发。

## 验收标准

- Node：旧回执数为 99/100/溢出边界的迁移、超过 100 次离线删除、版本持久化/重启、陈旧 outbox 拒绝、并发删除与重复请求、导出/删除类别级联均有测试。
- Android：首次模糊迁移逐类选择、Room/outbox 清理与隔离、崩溃恢复、版本对账后再发送；活动中断无惩罚；目标草案需确认才创建任务；探索日志区分待同步与已确认且重复收据不重复领奖。
- Web/Android 协议 fixture 一致；全量 Node、Android 单测、Lint、Debug 构建、敏感扫描、备份/恢复演练、性能预算和最新 GitHub Actions 通过。
- Xperia 电量和温度适合测试后，实测扫码/TLS pin、隐私导出/删除与长期离线恢复、日常活动、目标确认、三类线索/奖励、PTT 打断、ARCore 放置/追踪丢失回退、通知/小组件及两小时温度/电量/崩溃观察。没有实机证据的项目保持“待验收”；不得静默授予相机/定位权限。
- 正式签名仍以独立加密恢复副本实际验证为前置门槛；APK 不进入源码历史。各批独立提交到 `feature/integrated-enhancement`，同步更新 `README.md` 与 `HANDOFF.md`，不改 `main`。

## 明确不做

- 不新增角色数量、多人/社交、在线地图、默认后台定位、相册/原图云存储、签到压力或自治工具范围。
- 不将本设计视作实机/正式发布已完成；设备相关项必须由实际设备证据关闭。

## 假设

- 新增日常与目标功能默认由 Android 和 Web 双端完整操作；若用户审阅时要求 Android 先行，可在实施计划中缩小首批 UI 范围而不改变协议与持久化设计。
- 旧版回执恰好达到 100 条时无法推断更早类别删除记录，因此对所有旧类别逐类询问；保留本机数据时旧 outbox 隔离而非自动上传。
- 手机恢复测试前重新读取设备状态；低电量、过热或权限未由用户授权时跳过相应实机负载并如实记录。
